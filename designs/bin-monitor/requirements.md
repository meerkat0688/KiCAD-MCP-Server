# 垃圾桶滿載監視器：第 1 關需求契約
版本：v0.1｜日期：2026-11-17｜狀態：DRAFT，供需求審查，尚未完成產品驗收

## 1. Goal｜目標與完成定義
設計一套監視單一垃圾桶的原型系統。當垃圾高度持續達到設定門檻時，自動向指定 LINE 群組發送清運提醒；清空後自動恢復監視，避免同一次滿載重複洗版。

產品完成：下列必要需求均有實際測試證據，整合驗收通過，必要待確認項目已關閉。
第 1 關完成：需求、假設、驗收方式與停止條件已寫清楚，並由需求負責人確認基線。這不表示電路、PCB 或實體產品已通過驗收。
本文件數值均為本專案建議基線，不是引用文章的規格，也不是已量測結果。當前所有測試均為 NOT RUN。

## 3. Constraints｜可驗收需求

### 3.1 偵測與狀態
v0.1 優先評估頂部向下的非接觸距離感測，不預先鎖定超音波或 ToF 料號。是否需要多點量測，由實際垃圾形態測試決定。本版不要求攝影機或影像 AI。

定義：
- H：空桶時，固定感測面至桶底的校正距離。
- d：同一固定感測面至垃圾表面的有效距離。
- 垃圾高度占比 F = clamp((H − d) / H × 100%, 0%, 100%)。
- F 是感測位置的高度估計，不是重量、實際體積或整桶容積百分比。偏斜、架橋與局部凸起可能影響讀值；若需求是整桶體積滿載，必須重新設計量測方式。
- 建議每 5 秒取得一筆讀值，以最近 3 筆有效值的中位數為判斷輸入；不足 3 筆時不判定滿載。滿載與清空計時均自首次滿足門檻的濾波值起算。
- 任一無效量測中斷持續條件計時；連續 30 秒無有效值，進入 SENSOR_FAULT，不得當成空桶或滿載。

| ID | 需求 | 驗收條件 |
|---|---|---|
| SEN-01 | 支援空桶校正 | 保存 H 並於重啟保留；校正失敗時明確顯示未校正，不輸出滿載判斷 |
| SEN-02 | 基本距離量測 | 在選定感測器可用量程內，以平面靶放在 F=20%、50%、80%、90% 對應位置，各測 10 次；每次距離誤差 ≤2 cm。此測試不能替代真實垃圾測試 |
| SEN-03 | 確認滿載 | F ≥80% 持續 60 秒後產生一次滿載事件；低於門檻或無效值均重新計時 |
| SEN-04 | 過濾短暫遮擋 | 正常狀態下遮擋 10 秒後移除，重複 20 次，誤發滿載通知為 0 次 |
| SEN-05 | 清空與重新待命 | F ≤50% 持續 120 秒後回到 NORMAL 並重新允許下次滿載通知；50%<F<80% 時保持先前已確認狀態，不反覆切換 |
| SEN-06 | 異常量測 | 斷開感測器、模擬通訊超時及超出可用量程，各 3 次；全部進入 SENSOR_FAULT，且不產生新滿載事件 |
| SEN-07 | 真實垃圾適用性 | 以 IN-04 三類垃圾各完成 10 次滿載／清空循環，滿載與清空正確識別各至少 29/30；真值以事先標示的測點高度及量尺確認，保存照片與讀值。不宣稱通過此測試即代表體積量測正確 |
| SEN-08 | 桶蓋與安裝干擾 | 有桶蓋時開關蓋 20 次，無誤發；若桶蓋遮住感測路徑，須加蓋狀態偵測或改變安裝方式後重測 |

### 3.2 LINE 通知與故障處理
建議資料路徑：距離感測器 → 控制器 → Wi-Fi → 通知服務 → LINE Messaging API → 指定群組。
通知服務可部署於受管理的後端；LINE channel token 原則上保存在後端，不寫入公開程式或 PCB 文件。控制器平台與後端部署位置尚未定案。

| ID | 需求 | 驗收條件 |
|---|---|---|
| MSG-01 | 群組可達 | 官方帳號啟用加入群組並已加入目標群組；由 webhook 取得正確 groupId；在測試群組人工確認收到一則測試訊息 |
| MSG-02 | 通知內容 | 包含裝置／桶號、位置、偵測時間、估計高度占比、請清運文字；占比明示為高度估計 |
| MSG-03 | 通知時效 | 網路及 LINE 正常、額度足夠時，從第一筆有效的滿載門檻濾波值起，90 秒內在群組看見訊息；測試 10 次全部達成。API 接受與群組可見分別留證，200 回應不等同人工已讀 |
| MSG-04 | 防止重複 | 同一次滿載事件僅發 1 則滿載訊息；持續滿載 2 小時不追加提醒。每個事件有唯一 ID；裝置或後端重啟後仍遵守 |
| MSG-05 | 斷網補送 | 保存尚未完成的事件；測試斷網 10 分鐘且仍滿載，復網後 120 秒內補送 1 則，標示原事件時間及延遲送達 |
| MSG-06 | 過期與已清空事件 | 復網前若已確認清空，或事件超過 24 小時，取消未送滿載提醒並留存原因，避免送出過期清運指令 |
| MSG-07 | API 失敗 | 對暫時性錯誤採有上限退避重試，例如 5、15、60 秒後，改為每 5 分鐘；同一事件重試沿用相同 LINE retry key。憑證或群組設定錯誤、額度不足時顯示通知異常，不無限快速重試；保存狀態碼與失敗原因 |
| MSG-08 | 重新啟動 | 滿載已通知、滿載待送、正常三種情境各重啟 3 次；不重複通知、不遺失待送事件，重新取樣確認後才送出尚未完成的提醒 |

LINE Notify 已於 2025-03-31 終止，因此本案使用 Messaging API。群組人數會影響訊息用量；正式上線前需核對官方帳號方案及額度。重試只降低重複機率，不宣稱端到端 exactly-once 保證。

訊息範例：
> 【垃圾桶清運提醒】  
> 桶號：BIN-001｜位置：一樓公共區  
> 狀態：已達滿載門檻  
> 估計垃圾高度：85%（非容積）  
> 偵測時間：2026-11-17 15:30，Asia/Taipei  
> 請安排清運。

### 3.3 硬體、操作與紀錄

|---|---|---|
| HW-01 | 低壓供電 | 於 4.75、5.00、5.25 V 各執行量測及 Wi-Fi 傳送 30 分鐘，無異常重啟；記錄峰值／平均電流與電源軌最低電壓 |

| REL-01 | 長時間運行 | 連續運行 72 小時，無人工重啟；包含至少 24 小時已知未滿情境，誤發滿載 0 次；每日執行滿載／清空循環並保存紀錄 |

## 4. Allowed actions｜允許動作
- 閱讀本契約、官方 datasheet、LINE 官方文件及工具文件。
- 比較控制器、距離感測器、電源與連接器候選方案。
- 建立系統方塊圖、I/O 表、原理圖、韌體／後端設計、BOM、測試計畫與證據紀錄。
- 在專案目錄中建立及修改設計檔，執行可重現的靜態檢查、模擬及受控測試。
- 於帳號與群組由負責人完成配置後，在指定測試群組驗證通知。本契約不代表目前已取得憑證或已被要求發送訊息。

## 5. Forbidden actions｜禁止動作與不在本版範圍
- 不採用已終止的 LINE Notify；不猜測 token、groupId、MPN、pin mapping 或感測器量程。
- 不把單點高度宣稱為準確容積，不把手部遮擋或感測失敗直接判成滿載。
- 不將尚未執行的測試標為 PASS，不將 ERC／DRC 通過當成產品功能或可量產證明。
- 本階段不採購、不送板、不輸出製造檔；相關工作需另立下一階段範圍。
- 不含市電直接接入、自製充電電路、自動壓縮／開蓋、垃圾分類、重量測定、攝影機辨識、多桶管理、App 或正式戶外防水認證。

## 7. Stop conditions｜停止與阻擋條件
| 條件 | 狀態與處置 |
|---|---|
| 桶體尺寸／蓋子／垃圾形態未確認 | 可比較方案；固定方式、感測器最終選型與機構定版為 BLOCKED |
| 有效量程、視角或近距離盲區無法覆蓋 F=80% 位置 | 停止該候選方案定版，改位置或換料後重新驗證 |
| 缺 MPN、datasheet 或 footprint／pin mapping 未確認 | 該元件及後續 PCB 放行為 BLOCKED，不補造通過結果 |
| 無 Wi-Fi、LINE 憑證、群組授權或可用額度 | 可完成本機偵測；LINE 端到端驗收為 BLOCKED |
| 真實垃圾造成反覆誤判或漏判 | SEN-07 記 FAIL；評估多點感測或調整定義，修改門檻需更新版本並重測 |
| 任一必要需求 FAIL、BLOCKED 或 NOT RUN | 不宣告產品完成；說明缺少的證據與可繼續的獨立工作 |

原型可先用開發板與感測模組完成端到端驗證，再決定是否需要客製 PCB。最終節點名稱、電阻電容值與封裝，須在選定真實零件後納入受控附件；本關不憑空指定。

## 9. 可直接交給 AI 的工作指令
讀取 requirements.md，依 Goal、Inputs、Constraints、Allowed actions、Forbidden actions、Outputs、Stop conditions 執行。
先輸出需求追溯表、架構候選比較、資料／狀態流程、I/O 與電源預算，以及最少元件的原型驗證計畫。
優先驗證真實垃圾量測和 LINE 群組通知，再進入客製 KiCad 設計。
保留本文需求 ID；任何建議更動另列差異與理由，不默默改規格。
缺少桶體尺寸、真實料號、datasheet、pin mapping、模型或憑證時，把受影響項目標為 BLOCKED，說明缺什麼及哪些獨立工作仍可進行。
所有未執行驗證標為 NOT RUN；沒有板檔的 DRC 標為 N/A。
不得自動採購、送廠或宣告可量產。
